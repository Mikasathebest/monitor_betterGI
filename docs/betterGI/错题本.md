# 错题本 — 每次运行前必读

> 规则：**每次启动自动化（一条龙 / 配置组 / 任何远程操作）之前，先把本文件读一遍。**
> 犯过的错不许犯第二次。新犯的错当天记录到此文件。

## 0. 米哈游协议弹窗 + 版本过期（2026-09-26 一条龙全失效根因）⭐

**症状**：9/23 起三个场次全废，BGI 日志刷屏 `未能返回主界面`（1700+ 次），一条龙疑似"假跑"。

**根因（两层）**：
1. 米哈游推送用户协议 v62（本地已同意 v61）→ 游戏启动强制弹「协议更新提示」**内嵌 WebView 弹窗**。door_clicker2 盲点中心永远碰不到右下角「同意」按钮。
2. 该 WebView 弹窗**过滤一切用户态合成输入**：SendInput / mouse_event / keybd_event / PostMessage 全部无效（实锤）。只认真实硬件输入。
3. 叠加第二障碍：游戏版本 7.0.0 过期，启动器需更 9.79GB（大版本跨度还要校验 136GB）。

**修复**（`scripts/win/fix_protocol.ps1`，改前已备份注册表到本地 `genshin_registry_backup.reg`，**勿提交 git，含账号标识**）：
- 注册表 `HKCU:\Software\miHoYo\原神` 下协议版本 JSON 的 `major` 改为服务器版本、`minimum` 改 0，两个 `SHOW_FLAG` 置 `false` → 伪造"已同意"状态，弹窗不再出现。
- 注册表路径含中文「原神」时，ps1 必须 UTF-8 BOM，或用 `[char]0x539F + [char]0x795E` 码位构造路径（GBK 误读为鍘熺的坑）。
- 游戏版本过期：走 HYP 启动器点「更新游戏」。

**注意**：协议每次大版本可能再升级 → 弹窗会再来，届时重跑 fix_protocol.ps1（把 major 改成服务器当前版本）即可。

## 1. 登录卡门（卡登录背景 / 无"点击进入"）⭐ 最高频

**症状**：游戏启动后画面停在登录背景，长时间不出现"点击进入"；或出现了但点击无效；截屏逐字节不变（画面冻结）。

**已确认的诱因**：
- 直接启动 `YuanShen.exe` 时登录 SDK 偶发假死（2026-09-11、09-15 各一次）。
- **启动后 5 分钟内反复点击/发按键会干扰初始化**，越点越卡（坑：以为没点上就狂点）。
- Session 0 发出的鼠标事件游戏收不到（UIPI/输入隔离），点了也白点。

**正确做法**（2026-09-16 用户定稿 + 隐藏点击器修复）：
1. 启动后**安静等 2 分钟**（有更新另算），什么都不点。
2. 然后启动**隐藏点击器** `door_clicker2.ps1`（经 `run_s1_hidden.ps1` → wscript 运行，**无控制台窗口**），每 6s 盲点一次游戏窗口中心。
3. 每 30s 截图 CV 验证一次：进了大世界**立即杀掉 door_clicker2 进程**（按 CommandLine 匹配）。
4. **门上沙漏 = 正在连服务器，此时点击无效**，等沙漏消失；先排除代理问题（`fix_proxy.ps1`：Clash 没跑就必须关系统代理）。
5. 超过 ~8 分钟仍进不去：杀 `YuanShen.exe` 重开，重开后从第 1 步重来。
6. 判断"真卡死"的依据：连续多次截屏**逐字节相同** = 画面冻结，重开。

**点击落空的最大元凶（2026-09-16 实锤）**：可见的 PowerShell 控制台窗口抢前台 + 遮挡游戏窗口 → 点击坐标落在控制台/BGI 窗口上而非游戏。修复：**一切点击/UI 操作走 `run_s1_hidden.ps1`（wscript 隐藏运行）**，只有 UIA 类才用可见的 `run_s1.ps1`。残留控制台用 `clean_desktop.ps1` 清理。

**2026-09-26 补充（7.1 版本）**：
- **SendInput 点门失效**：窗口已前台、坐标正确，SendInput 连点两次门不开；`PostMessage(WM_LBUTTONDOWN/UP)` 一次即成。`enter_door.ps1` 已改为 PostMessage 方案。
- **PostMessage 必须配 `SetCursorPos`**：Unity 按**真实光标位置**（Input.mousePosition）而非消息 lParam 命中 UI。不移光标的 PostMessage 点不中目标（实锤：不开光标点空白区关不掉详情卡，移光标后成功）。
- **PrintWindow 抓不到 UI 层**：游戏窗口未被 DWM 合成（未置前台/被遮挡未绘制）时，`PrintWindow(flags=3)` 只输出 3D 场景，**UI 层（点击进入/按钮/弹窗）全部缺失**，画面看起来"永远没加载完"。诊断必须看真实桌面截图（`grab_screen.ps1` CopyFromScreen），别只信 PrintWindow，否则会误判"卡死/着色器预热"白等 25 分钟。

## 2. 队伍必须用「大世界」

**症状**：自动战斗/锄地时角色不放技能、打得极慢。

**原因**：ScriptGroup 的 `pathingConfig.partyName` 为空 = 不切队，沿用游戏内当前队伍。游戏内停在「星扩散」（无攻击配置的队伍）时全程刮痧。

**修复（2026-09-15 已做）**：`全自动循环 / 采矿 / 钓鱼 / 伊安珊材料` 四个组的 `partyName` 已改为 `大世界`；一条龙 `默认配置.json` 的 `PartyName` 本来就是 `大世界`。
**注意**：改的是磁盘文件，BGI 重启后才加载（每天 22:30 场次会重启 BGI，自然生效）。

## 3. 邀约自动化 —— 已放弃（2026-09-15 用户决策）

**经过**：自研 v13 伺服导航（三角定位 + 相机伺服 + 卡死逃脱）实测失败：
- 三角定位样本被 OCR 噪声污染（读数跳变 65m→82m），算出的目标点是错的；
- 裸伺服导航（无地图路径点）撞墙后掉下山，爬不回来，最终人工传送+走路解决；
- JS 任务还在 ~2 分钟时被 BetterGI 内部取消（`A task was canceled`，原因未查明，疑内部超时/热键冲突）。

**结论**：BetterGI 自动邀约只负责**自动选对话选项**，导航/跑路不要自己造轮子。邀约改为人工跑图 + BGI 触发器自动选选项（`autoHangoutEventEnabled=true` 保持开启即可）。
**教训**：没有地图路径文件（AutoPathing json）的裸坐标伺服导航不可靠，别再写。

## 4. 远程操作 Windows 的硬规则（反复踩过）

- **UI 操作必须在 Session 1**：SSH 进来是 Session 0，看不到也点不动 GUI。UIA/点击一律走 `schtasks` 计划任务（InteractiveToken）。
- **PS1 含中文必须 UTF-8 BOM + CRLF**：用 `scripts/to_win.py` 转换后再 scp，否则 PowerShell 5.1 按 GBK 解析直接乱码/报错。
- **cmd 命令行里别写中文**（findstr/echo 等），中文一律放 ps1 文件里跑。
- **大 JSON 别用 PowerShell `ConvertFrom-Json` 改**（630 任务的组文件会卡死/丢格式），拉到本地用 python 改完推回去。
- 一次性调试计划任务用完 `/sd 2099` 防呆或用完即删。

## 5. Agent/截图/焦点（2026-09-16 新增）

- **截图必须走 Session 1 计划任务**：SSH 直跑 `screen.ps1` 报 `CopyFromScreen 无效参数`（Session 0 拍不到 Session 1 桌面）。用 `shot_s1.ps1` 注册一次性任务拍。
- **任何 Session 1 操作都抢前台焦点 → BGI 暂停**：截图/点击/UIA 后游戏重新获焦才恢复。操作间隔 ≥30-60s，拿日志验证后再下一步，别密集操作。
- **"已点击" ≠ 已进门**：门界面点击后必须用截图确认进了大世界；卡登录背景时点击不生效，杀游戏重开。
- **CV 视觉模型可用**：`nvidia/qwen/eccn-qwen3.5-122b-a10b`（chat completions 带图）识图准确（门/大世界/队伍/弹窗），Agent 的 screenshot 工具已内置，判断状态以它为准，不要猜。
- **计划任务结果码 0xC000013A (3221225786)** = PowerShell 被外部强杀（下线脚本清理残留、或**用户手滑关了 Session 1 桌面上可见的控制台窗口**——09-17 15:36 事故）。不是一条龙/BGI 失败码。**根治：`BGI_Session` 已改为 `wscript run_hidden.vbs` 隐藏启动，桌面上根本没有控制台可关。**
- **PowerShell 5.1 没有三元运算符 `?:`**，写了直接报错。
- **严禁"定时地雷"脚本（2026-09-16 09:29 事故）**：Windows 脚本里写 `Start-Sleep 180 + Stop-Process YuanShen` 这种延时逻辑 = 地雷——Agent 进程被杀后脚本照样到点爆炸，把别人刚起好的游戏杀掉。等待/重试节奏由 Agent 侧工具轮询控制，Windows 脚本只做即时动作。排查用 `kill_landmines.ps1`。
- **Agent API 400 两连坑**：Azure 后端的 Responses API ①拒绝非 `msg_` 前缀的 output id（`chatcmpl-` 直接 400）②拒绝 `_encrypted_content_affinity_pinned` 等加密字段。修复：回传 output 时手工重建，只保留白名单字段（message→role+content 文本，function_call→call_id+name+arguments，reasoning 不回传）。

## 6. 大组"假跑"识别（2026-09-16 04:30 事故）⭐ 监控必查

**症状**：路线任务以 ~9s/条 连环"完成"，传送=0、拾取=0、战斗=0，ERR 刷屏 `未能返回主界面`。
**根因**：进门后月卡/活动等弹窗未关，游戏 UI 不在主界面 → SwitchParty 等所有 UI 导航失败 → 每个任务快速失败但被记为"执行结束"，书签照样前进，**630 条全假完成为真实收益 0**。
**识别**：任务完成数暴涨但 传送/拾取=0 即为假跑；健康路线应 >20s 且有传送记录。
**处理**：截图确认并关掉弹窗 → `python set_bookmark.py CLEAR` 清书签 → 重跑。一条龙自检报"未领取"时同理。
**预防**：F9/大组启动前先截图确认无弹窗（已写进 Agent 定时任务 mission）。

## 7. 2 小时死循环事故（2026-09-16 全天）⭐ 架构级教训

**症状**：计划场次是 6h（04:30/10:30/16:30/22:30），实际每 ~2h 就重启一场（12:24/14:24/16:24/18:24/20:24/21:54/23:24），每场都杀光重来。

**根因（三连环）**：
1. **F9 流程自带配置组续跑**——"一条龙和配置组任务结束"标记要全流程（十几小时）跑完才出现，`session_online` 等它 40 分钟**永远超时**；
2. 超时后脚本用 UIA 去"续跑大组"——但大组已经在跑，UIA 乱点（"已点全自动"）**把健康流程打断** → 日志静默；
3. 看门狗 25 分钟判静默 + 40 分钟冷却 → 再次触发 `BGI_Session` → 杀光重启 → 回到 1。

**附带伤害**：`session_online` 第一步"杀残留"无差别杀 `YuanShen.exe`——**用户手动开的游戏也被杀**（21:54 事故，用户正在玩被踢下线）。

**修复（session_online v2，2026-09-16 23:30 上线）**：
- **手动游戏保护**：`PHASE=OFFLINE` + 游戏在跑 + BGI 没跑 = 用户手动游戏 → 跳过本场次，不杀不碰；
- **删掉 40 分钟等待**：F9 后只验证日志活性（文件增长），不等完成标记；
- **删掉主动续跑大组**：仅当 F9 后日志静默时兜底补一次进门点击 + 重发 F9，绝不 UIA 点组；
- 进门按用户定稿：120s 安静 + 隐藏点击器 6s/次 × 180s。
- **教训：等待条件必须是你确定会出现的信号**；"补启动"类操作前先确认目标真的没在跑，否则就是打断。

## 8. "跑完空闲" ≠ "卡死"（2026-09-17 看门狗误报）

**症状**：流程 05:41 全部跑完（大组书签接近末尾，实际任务量只有 ~1h），BGI 空闲 → 日志静默 43 分钟 → 看门狗 06:24/08:24 两次"恢复"重启 → 钓鱼组白跑两遍（鱼点没刷新），会话窗口被延到 11:24。
**根因**：看门狗只用"日志静默 ≥25min"判卡死，分不清"卡住"和"已完成空闲"。
**修复（看门狗 v3）**：判定静默时先查日志最后的任务事件是不是 `一条龙和配置组任务结束`（与最后时间戳相差 ≤5 分钟）→ 是 = 流程已完成 → 直接 `cycle_offline -Complete` 提前下线（符合"跑完就关游戏"），**不重启**。
**配套认知**：钓鱼路线单条 1.5-3 分钟且有长静默期；"鱼点没鱼"时日志 `10秒没有确认初始状态和找到鱼，结束任务` 属正常。一条龙结尾自检报"未领取"是已知误报，以 `已领取` 计数为准。

## 9. 顶号检测与跳过（2026-09-27 新增，用户规则）

**规则**：一轮内检测到账号被顶（重复登录）≥2 次 = 用户在其他设备手动玩 → **跳过本轮一条龙，直接下线**。

**原理**：BGI 对顶号完全无日志（GameLoading 点 ChooseEnterGame 是静默的），但游戏每次进门都会在 `MiHoYoSDK.log` 写一条 `into LoginManager::Login`。被顶→回门→点击器重进→必多一条登录记录。

**实现**（session_online.ps1）：
- 起游戏前记基线 `loginBase`（Count-Logins 数 `into LoginManager::Login` 条数；读失败返回 -1 则本轮不启用检测）
- delta = 当前数 - 基线；1=自己开局，每再 +1 = 被顶重进一次；**delta≥3（被顶≥2次）触发跳过**
- 检查点：进门阶段结束后一次 + 一条龙等待循环每 2min 一次
- 触发动作：记日志 → 调 `cycle_offline.ps1`（杀游戏+BGI、置 OFFLINE；它会顺手把 session_online 自己也杀掉，属预期）

**注意**：SDK 日志路径含中文「原神」，用 `[char]0x539F + [char]0x795E` 码位构造，别在 ps1 里直接写中文路径。
