### 14.3 新坑：macOS tar 的 AppleDouble 垃圾文件

macOS 上 `tar -cf` 打包含 CJK 文件名的目录时，会给每个文件生成一个 `._文件名` 的 AppleDouble 元数据文件。解压到 Windows 后 `._*.json` 混在路线目录里，**BGI 可能尝试加载它们**。修复：解压后 `Get-ChildItem -Recurse -Filter "._*" | Remove-Item`。以后打包用 `COPYFILE_DISABLE=1 tar -cf` 避免生成。

### 16.2 本轮新经验

| 坑 | 现象 | 结论 |
|---|---|---|
| **ListItem.Name 是类名** | 按名选组失败，5 项全叫 `BetterGenshinImpact.Core.Script.Group.ScriptGroup` | WPF ListBoxItem 的 UIA Name 返回**类型全名**；真实显示名在**子级 Text 元素**里 → 遍历 item 的 Descendants(ControlType.Text) 拼接再匹配（v2 脚本已修，5 组显示名全部正确读出） |
| **BGI 日志文件被独占锁** | `ReadAllLines` 抛 IOException | BGI 持锁写日志；读日志必须 `FileStream` + `FileShare.ReadWrite` |
| **LastWriteTime 元数据滞后** | 目录列表显示 19:47，但文件里已有 20:09 的内容 | Windows 文件元数据刷新有延迟；**别用 LastWriteTime 判断日志活性**，直接共享读内容看时间戳 |
| 按索引选组脆 | 组顺序变就选错 | 一律用按名版 `uia_start_group_named.ps1` |

### 16.4 首跑结果与 AutoPathing 大坑

**首跑 22 分钟，9/24 成功**：
- 琉鳞石 6/6 ✓（拾取 40+ 个）

**教训**：
1. **加路线先查 `User\AutoPathing\`** —— 仓库同步器大概率已经帮你下好了（隙境原体 3 条、琉鳞石 6 条本来就在，白下载了）
2. 手动部署必须进 AutoPathing，MapPathing 部署了也白搭
3. 引用不存在的路线 = 0.003 秒假成功（日志写"脚本执行结束"但耗时 0 秒 + 前面有异常）——**验证路线不能只看"执行结束"，要看耗时和拾取记录**
