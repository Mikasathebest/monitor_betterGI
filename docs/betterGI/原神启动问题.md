## 12. 第四轮教训：锁屏 = 全线瘫痪（2026-09-14 上午）

| 坑 | 现象 | 结论 |
|---|---|---|
| **Windows 锁屏** | BGI 启动卡死在 `ScriptRepoUpdater` 之后（进程活着、0 繁忙线程、无窗口）；UIA 枚举不到任何窗口 | 锁屏后无交互桌面，`OpenInputDesktop` 失败，MaskWindow/GraphicsCapture 初始化死锁。**整套自动化（BGI 启动/UIA/截图/输入）都要求会话未锁** |
| 检测方法 | `LogonUI` 进程存在 + `OpenInputDesktop` 返回 0 | 两个都中 = 已锁屏 |
| 修复 | 注册表：`HKLM\...\Policies\System InactivityTimeoutSecs=0`、`HKCU\Control Panel\Desktop ScreenSaveActive=0 / ScreenSaverIsSecure=0`、动态锁 `EnableGoodbye=0` | 已写入 `disable_lock.ps1`；**但用户手动 Win+L 仍会锁**，需注意 |
| 一次性测试任务 | `schtasks /sc once /st 23:59` 创建的调试任务会在当晚 23:59 全部误触发（乱点击/抢焦点） | 调试任务用完立刻 `schtasks /delete`，或 `/sd 01/01/2099` 永不自动触发 |
| `schtasks /sd` 日期格式 | `2026/09/14` 报错 | Windows 中文系统要 **dd/mm/yyyy**（`14/09/2026`） |
| SSH 里 `Get-Process` 返回数组 | 多实例时 `$p.Id` 变成数组，`-eq` 比较全失败 | 一律 `@($procs)` 包装再遍历 |
| SSH 内联 PowerShell 双引号 | `$` 变量被本地 shell 吃掉 | 复杂逻辑必须写 .ps1 文件再执行，别内联 |

**电源状态**：显示器 AC 电源 = 永不关闭（0x0），无需改动；锁屏是唯一杀手。

**当前遗留**：BGI 在锁屏期间启动的实例会永久卡死（无窗口），解锁后需杀掉重启。


## 13. 第五轮教训：Session 0 诊断盲区 + 截图器不自启（2026-09-14 中午，游戏更新日）

**事故经过**：游戏客户端自动更新（校验文件→退出→重启进登录界面），之后 BGI 三次启动都"无窗口卡死"，日志停在 `ScriptRepoUpdater`。排查 1 小时后发现**两个叠加问题**：

### 13.1 Session 0 的诊断全是假的

| 诊断手段（从 SSH 直连运行） | 显示 | 真相 |
|---|---|---|
| `Get-Process.MainWindowHandle` | 0 | WPF 应用此值本来就不可靠，常为 0 |
| `EnumWindows`（SSH 直连） | 0 个窗口 | **Session 0 只能看到 Session 0 的窗口**！BGI 窗口在 Session 1 好好活着 |
| `OpenInputDesktop` 失败 + LogonUI 存在 | "锁屏了" | Session 0 调这 API 永远失败；LogonUI 检查也是误报 |

**铁律：所有窗口/桌面诊断必须经 `schtasks` 任务（Session 1）运行，SSH 直连的诊断结论一律不可信。**

### 13.2 截图器开机不自启

- BGI 0.64.2 开机后**截图器不会自动启动**（主页显示"BetterGI 截图器，启动！"按钮）。今早 09:37 能自启是因为当时游戏状态正常；游戏更新后（小窗口/登录界面）自启失败就再不重试。
- 症状：主窗口在、消息循环正常（dotnet-stack 证实无主线程阻塞）、但 MaskWindow/TaskRunner 不起，日志停在 ScriptRepoUpdater。
- **修复**：UIA `InvokePattern` 点主页 `Button "启动"`（`uia_start_capture.ps1`）。已集成进 `online_start.ps1` 第 2 步。

### 13.3 本轮其他坑

| 坑 | 现象 | 结论 |
|---|---|---|
| **C# `out _` 语法** | Add-Type 编译失败，后面全崩 | **PS 5.1 的 Add-Type 用 C# 5 编译器**，不支持 `out _` 丢弃符（C# 7+）；改用 `out dummy` 变量 |
| PS 默认 `ErrorActionPreference=Continue` | Add-Type 编译失败不中断，脚本"带伤"跑完，日志全是误导 | 关键脚本开头加 `$ErrorActionPreference='Stop'` + try/catch 写日志 |
| **wscript 隐藏进程** | 枚举到 0 个窗口 | wscript 拉起的隐藏 PowerShell **不在交互桌面**，EnumWindows 失明；要桌面访问必须**直接 powershell 做任务动作**（控制台会闪一下，可接受） |
| 计划任务 PowerShell 控制台 | 每次运行抢前台 | 游戏 raw input 只在**前台**收鼠标；点击游戏前必须先把游戏置前台 |
| 游戏只认 SendInput | `mouse_event` 点击游戏无效 | 游戏（Unity raw input）只响应 `SendInput`；BGI 界面（WPF）两者都认 |
| 0.64.2 导航结构 | 找不到"调度器" | 调度器是 **"全自动" 的子菜单项**（全自动→调度器/JS脚本/地图追踪/录制回放） |
| 游戏更新 | 更新界面卡死一切 | 更新日：等更新完→游戏到登录界面→起 BGI→启动截图器→开大组→**BGI 自动开门会自己点进游戏**（前提是截图器在跑） |

**最终可用的全无人值守上线序列**（已验证，集成在 `online_start.ps1`）：
`BetterGI_Run 起 BGI` → `uia_start_capture.ps1`（Invoke 主页"启动"）→ 等游戏加载 → `uia_start_group.ps1`（枚举找窗口→强置前台→全自动→调度器→选组→运行）→ BGI 自动开门进游戏 → 从书签续跑。

## 14. 系统代理断网坑（2026-09-15 用户发现）

**现象**：重启后原神连不上网、无法登录。

**根因**：桌面 VPN（FlyintPro/Clash）开启时会把 Windows 系统代理（`HKCU\...\Internet Settings\ProxyEnable=1`）指向 `127.0.0.1:7890`。**重启后 Clash 没自启，但系统代理还开着** → 所有流量发给一个没人监听的端口 → 原神断网。

**修复（已自动化）**：`fix_proxy.ps1` —— 探测 7890 是否有监听：
- 代理开 + 7890 无监听（Clash 没跑）→ **关系统代理走直连**（国服直连即可）
- 代理开 + 7890 在听（VPN 正常）→ 不动
- 代理关 → 不动

已嵌入 `session_online.ps1` 步骤 0.02（每次起游戏前必跑），重启/定时触发全覆盖。Clash 之后若自启会自己重新打开系统代理，两向自愈。

**手动操作（若需现场处理）**：设置 → 网络 → 代理 → 关"使用代理服务器"；或开 FlyintPro 确认代理 127.0.0.1:7890 在听。
