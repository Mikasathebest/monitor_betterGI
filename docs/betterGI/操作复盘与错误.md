## 3. 失败的部分（UI 鼠标自动化）与根因链

用户在 Windows 现场看到的现象：**弹出多个 PowerShell 窗口、游戏里角色挥了一下攻击键、其余无任何效果**。
这与远程观察到的情况完全吻合。失败不是单一原因，而是一整条叠加的根因链：

### 3.1 PowerShell 配置文件挂起（最隐蔽的坑）

- 计划任务以 `powershell -File xxx.ps1` 启动，**没带 `-NoProfile`**。
- 用户机器的 PowerShell profile 加载了 Trae CN 终端集成脚本，在非交互场景下**直接挂死**。
- 证据：`Get-CimInstance Win32_Process` 抓到挂了 5+ 分钟的 `powershell.EXE -File C:\Users\djf20\click2.ps1` 进程。
- 后果：点击脚本**从未执行过**，但 `schtasks /run` 返回"成功"，极具迷惑性。
- 修复：任务命令行加 `-NoProfile -NonInteractive -WindowStyle Hidden`。

### 3.2 双会话（Session）迷局

- 机器上同时存在 **Session 1**（控制台，BetterGI + 原神所在）和 **Session 2**（另有 explorer 进程，疑似 RDP/快速切换残留）；SSH 本身在 Session 0。
- `schtasks /it`（InteractiveToken）在多会话下落到哪个会话**不确定**，必须用 `(Get-Process -Id $PID).SessionId` 自验证。
- 修复：所有诊断脚本自带会话 ID 日志，确认落在 Session 1。

### 3.3 截图是"陈帧"（最危险的假象）

- `CopyFromScreen` 在显示器休眠/锁屏后返回 **DWM 最后一次合成的画面**。
- 我看到的"BetterGI 首页/调度器页"其实是旧帧；**真实桌面是游戏在前台、BetterGI 被压在下面**。
- 后果：对着一个"看起来在那里、实际不在那里"的窗口点了十几次。
- 修复：截图脚本加 DPI 感知 + 绘制当前光标（`shot_cursor.ps1`），与旧截图对比才识破陈帧。

### 3.4 DPI 缩放坐标系混乱

- 桌面物理分辨率 **2560×1600，150% 缩放**（逻辑 1707×1067）。
- 早期点击按 1920×1080 估算坐标 → 全部落空。
- 教训：点击脚本必须 `SetProcessDPIAware()`，且坐标必须来自**同一坐标系**的截图。

### 3.5 游戏的鼠标捕获

- 原神前台时会**锁定并居中光标**（射击视角惯例），`SetCursorPos` 移过去会被吸回屏幕中心。
- 用户看到的"动了一次鼠标攻击键"：我的点击落进了游戏窗口 → 玛薇卡挥了一刀。
- 修复：先把 BetterGI 置前（见 2.最后一行），让游戏失去输入焦点。

### 3.6 UIPI 权限隔离

- BetterGI 以**最高权限**运行（计划任务 `HighestAvailable`）；SSH 会话非提权。
- UIPI 直接丢弃低权限进程发来的 `mouse_event`。
- 修复：点击也走高权限计划任务（`BGI_Click2`）。

### 3.7 UIA 不可用

- 试图用 UI Automation 按按钮名 `Invoke()`（免坐标方案），结果 `RootElement` 下**枚举到 0 个顶层窗口**——跨会话/桌面隔离导致 UIA 树不可见，此路不通。

### 3.8 根因链总结

```
没加 -NoProfile → 脚本挂死（点击根本没执行）
        ↓ 修复后
坐标按 1920 估算 → 全部落空（真实 2560×1600@150%）
        ↓ 修正后
截图是陈帧 → 对着"不在前台的窗口"点
        ↓ 用带光标的真截图识破
游戏捕获鼠标 + BetterGI 被压在下层 → 点击被游戏吃掉（那一刀）
        ↓ SetForegroundWindow 置前
UIPI → 非提权点击被丢弃 → 改走高权限任务
```

每一层修复后都还有下一层。这就是"看起来操作简单、实际总差一点"的原因。


## 4. 为什么 BetterGI 能又快又稳地采矿/传送，而我（远程 AI）不行

| 维度 | BetterGI | 我（SSH 远程操作） |
|---|---|---|
| 感知 | 本地 BitBlt 直抓游戏窗口画面，**每秒多帧** | 截屏→scp 回 Mac，**一次往返 6–10 秒**，还可能是陈帧 |
| 识别 | 本地 ONNX（小地图匹配/OCR），毫秒级 | 我用肉眼读低清截图，一次一帧 |
| 操作 | 进程内直接 SendInput，同会话同权限 | 跨会话、跨权限（UIPI）、跨 DPI 坐标系 |
| 导航 | 预录制路径点 JSON，**执行+校验**即可，不需要"看懂"世界 | 我得从像素重建全部状态 |
| 容错 | 战斗策略/自动拾取/神像回血/死亡恢复全内置 | 每一步都要远程确认 |
| 闭环延迟 | **毫秒级**感知-决策-动作闭环 | **秒级~分钟级**闭环，根本追不上实时游戏 |

一句话：**BetterGI 是"长在机器里"的具身智能体，感官和手都直连游戏；我是隔着 10 秒延迟、用着一只时不时被游戏抢走鼠标的远程操作员。** 实时控制环路对延迟的要求是硬性的，这不是智力差距，是物理差距。

## 8. 远程键盘注入的坑（第二轮教训）

目标：游戏外远程开地图读体力。试了 5 种方式，结论如下：

| 方式 | 结果 | 原因 |
|---|---|---|
| `keybd_event` | ❌ 被游戏过滤 | 老 API，游戏 raw input 不认 |
| `PostMessage(WM_KEYDOWN)` | ❌ 被忽略 | Unity 游戏不读消息队列键盘 |
| `SendInput` (32字节 struct) | ❌ 静默失败 | INPUT 联合必须按最大的 MOUSEINPUT 对齐到 **40 字节**，否则 ERROR_INVALID_PARAMETER |
| `SendInput` (40字节) + 游戏前台 | ✅ 成功 | 与 BetterGI 的 Fischless.InputSimulator 同款 API |
| 计划任务直起 PowerShell | ⚠️ 副作用 | 控制台窗口**抢前台** → BetterGI 检测到"焦点不是原神"**自动暂停采矿**；需 `wscript.exe xxx.vbs` 隐藏启动 |

**关键发现**：
- BetterGI 路径追踪有异常自愈：外源 M 键开地图 → 小地图定位失败 → 异常处理（传送重置）约 30 秒恢复，但会打断当前路线。**采矿运行时不要用外源输入戳游戏**。
- 连拍验证法：M 后 0.6/1.2/1.8/2.4/3.0s 连拍 5 张，抢在 BGI 自愈关地图前截到地图界面（第 2 张成功）。
- 体力读数验证：地图右上角 "原粹树脂 165/200"，图标模板 + OCR 区域 (icon.x, icon.y, 200, 40) 与 C# 内置任务一致。


## 11. 远程 UI 自动化第三轮教训（Session 0 / 陈旧帧 / UIA 测绘）

| 坑 | 现象 | 结论 |
|---|---|---|
| SSH 直接 `Start-Process` 起 BGI | 进程活着但**永远无窗口** | SSH 在 **Session 0**（无桌面）；GUI 程序必须经 `schtasks`（InteractiveToken）落到 Session 1 |
| 窗口最小化时 `CopyFromScreen` | 截图显示"最大化旧画面"，光标还能动 | **陈旧合成帧**！UIA 报窗口在 (-32000,-32000) 才是真相。先 `ShowWindow(SW_RESTORE)` 再操作 |
| 按旧截图坐标点击 | 全部落空 | 窗口位置/大小会变；每次操作前必须 UIA 测绘实时坐标 |
| 按钮名 "执行" | 找不到 | 这个版本 (0.64.2-alpha.3) 叫 **"运行"**；旧截图里是旧版文案 |
| UIA 全树遍历 | 卡死/超时 | 999 行 DataGrid 每行都有按钮；用 `FindFirst(类型+名称)` 精准定位，别 Walk 全树 |
| WPF-UI 导航项 | SelectionItem/Invoke 都不支持 | 只能鼠标点 BoundingRectangle 中心 |
| 启动自动兑换码任务 | 开机占住 TaskRunner 15 分钟 | `UseRedemptionCodeTask` 开机自动跑兑换码列表，焦点不在游戏就空转暂停；把游戏置前台即放行 |

**最终可用的组启动序列**（已验证）：`ShowWindow(9)` 恢复窗口 → 组列表 `ListItem`（名字是类名，按**索引**选）`SelectionItemPattern.Select()` → 找 `Button "运行"` → Invoke 失败就鼠标点矩形中心。


## 15. 加配置的正确姿势（2026-09-14 晚，本轮踩坑全记录）

本轮给大组加 24 条伊安珊路线，**花了 6 次 SSH 往返 + 4 个错误**，太慢。以下是错误和正确姿势。

### 15.1 本轮错误清单

| # | 错误 | 现象 | 根因 | 正确做法 |
|---|---|---|---|---|
| 1 | ps1 无 BOM | `TerminatorExpectedAtEndOfString`，CJK 字符串断引号 | **PS 5.1 把无 BOM 的 UTF-8 当 GBK 读** | 本地 `printf "\xEF\xBB\xBF" > f.ps1 && cat src >> f.ps1` 再 scp |
| 2 | 失败时吞了 stderr | 第一次部署 exit 1 无任何输出，盲猜一轮 | `2>/dev/null` 把解析错误藏了 | **首次跑新脚本别吞 stderr**；稳定后再静默 |
| 3 | tar -C 目标不存在 | `could not chdir to ...` | tar 不会自建目录 | 解压前 `New-Item -ItemType Directory -Force` |
| 4 | zsh 内联 ssh 命令 | `no matches found`，路径反斜杠被剥 | zsh 对双引号串做 glob/转义 | **复杂 PowerShell 一律写 .ps1 文件 scp 过去**，绝不内联 |
| 5 | PS ConvertFrom-Json 验证 | 218KB 组文件返回 projects.Count=0 | PS 5.1 大 JSON 解析不可靠 | 验证用 regex 计数/文件大小，或本地 python 验完再传 |
| 6 | macOS tar AppleDouble | `._*.json` 混入路线目录（见 §14.3） | macOS tar 默认带元数据文件 | 打包加 `COPYFILE_DISABLE=1` |

### 15.2 慢的根源与正确流程

慢的根因不是单步失败，而是**"下载→打包→上传→解压→验证"全串行、每步一次 SSH 往返、出错再重来**。

正确流程（本轮最终收敛版，共 **2 次 SSH**）：
1. 本地 python 一次构建全部产物（路线 + 组 JSON + 脚本），本地验证完
2. `COPYFILE_DISABLE=1 tar` 打包（ps1 已预置 BOM）→ 一次 scp
3. 远端**一个**带 BOM 的 deploy.ps1：解压 → 就位 → 验证 → 报告（`$ErrorActionPreference=Stop`）

### 15.3 加配置不需要退出原神/BGI

- 路线文件（MapPathing）和组文件（ScriptGroup）是 BGI **启动时**（或调度器页手动刷新时）从磁盘加载的；部署新文件**不影响正在运行的任务**（运行中的组用的是内存副本）。
- 所以：游戏照跑、BGI 照跑，文件直接覆盖部署；下次 BGI 启动（或 UI 刷新）自动生效。
- 唯一例外：想让**当前正在跑的组**立刻用新内容，才需要重启 BGI 或重新选组。

### 15.4 按名选组

`uia_start_group.ps1` 按**索引**选组（脆：组顺序变了就选错）。本轮做了 `uia_start_group_named.ps1` 按**名称子串**匹配（遍历 ListItem 找名字含"伊安珊"的项再 Select）。以后启动脚本一律用按名版。
